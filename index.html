Why it's fast

Speed here isn't an optimization pass bolted on at the end. It's what's left when you don't add the slow things in the first place.

📄

Inlined critical CSS

Styles live in a <style> block in the head. No render-blocking stylesheet round trip, so first paint happens on the first packet.

🔤

System font stack

Uses the font already on the device. Nothing to download, no flash of invisible text, no layout shift when a webfont swaps in.

🚫

No JavaScript

Nothing to parse, compile, or hydrate. The page is interactive the moment it paints, and it works with JS disabled.

📐

Zero layout shift

Fluid type with clamp() and intrinsic grids mean the layout settles once. CLS stays at 0 without reserving hacks.

🔒

No third parties

No CDN scripts, no tag managers, no trackers. Every byte comes from one origin, so there are no extra DNS lookups or TLS handshakes.

🌗

Dark mode for free

A handful of CSS custom properties swapped under prefers-color-scheme. No toggle script, no flash of the wrong theme.

The performance budget

Rules that keep the page fast as it grows. Break one and you own the fix.

  • One request for first paint. HTML carries its own styles.
  • No blocking resources. Anything optional loads lazily or not at all.
  • Images ship modern and sized. WebP/AVIF, explicit width and height, loading="lazy" below the fold.
  • Under 14 KB compressed for the initial document — roughly one TCP round trip.
  • No dependency without a measurement showing what it costs.
<!-- The whole delivery model -->
<style> /* critical CSS, inlined */ </style>

<!-- Images: modern format, no reflow -->
<img src="hero.avif"
     width="1200" height="675"
     loading="lazy" decoding="async"
     alt="Descriptive text">

<!-- Fonts: already installed -->
font-family: system-ui, sans-serif;

<!-- JavaScript -->
// (intentionally left blank)

Ship it

Static files need no build step and no server. Push the branch, turn on GitHub Pages, and a global CDN serves it. 

git add index.html 404.html
git commit -m "Add site"
git push -u origin main

# Settings → Pages → Deploy from branch
# → main / (root) → Save
  • Edit index.html — it's the only file that matters.
  • Preview locally with python3 -m http.server, or just open the file.
  • Measure in DevTools → Lighthouse before adding anything new.
  • Keep the budget and the site stays this quick a year from now.
